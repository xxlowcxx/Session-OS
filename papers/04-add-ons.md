# Add-ons

These close the gaps between a session and the feeling of a full OS.

1. **Unlock handoff.** The session is loaded and waiting while the phone is on its lock screen. The instant the owner is in, the session is the screen. On an Android the owner configured, their own code is that screen.

2. **Local snapshot.** The last desktop, files, and button state sit on the device. Offline, the session still opens. The server catches up when the radio is back.

3. **Memory tiers.** The working set stays in the phone's RAM. The next layer sits on the phone's storage. The server holds the archive and the fine-tuning. Server memory stays on the server. The phone does not use it as RAM.

4. **Equivalence table.** The button table in paper 03, kept per OS, and updated when a phone gains or loses a finger.

5. **Session Wi-Fi book.** Networks are saved in the virtual OS. After the owner is in, the session hands that list to the phone through the normal Wi-Fi API. This is a session record. It is not space outside the OS, and it is not a way to add a system.

6. **Full-screen shell.** While the session is up, the host chrome is covered. The splash is the handoff. What the user sees from that moment is the virtual OS.

7. **Heartbeat.** A pulse walks the table. If the phone revokes a finger, that button drops to session-only instead of failing.
