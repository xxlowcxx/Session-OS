# Bounds

The session is the product. These are outside it.

- The phone's own OS is the boot. The session does not replace it.
- Apple's iOS runs on Apple hardware. A Samsung does not boot it. The session can feel like the system the owner picked, through the table and the screen.
- A locked phone, or a phone that is not set up, does not run the session. The handoff waits until the owner is in, or until an Android they set up uses their code as the lock.
- The Wi-Fi setup screen saves a network name and a password inside the OS that already booted. That record cannot hold a second OS.
- The session does not inject during boot, overwrite a settings option into a port, trap the host OS, or run when the host refuses to start it.
- A server that manages a phone can lock it, wipe it, or push an app and a profile the phone already accepted. It cannot make the hardware start one of the systems in the menu.

The experience and the boot are different things. The experience is what we are building.
